# سامانه‌ی ثبت‌نام اردو — مجموعه‌ی جریان

ثبت‌نام اردوی بازدید علمی از ساختمان مرکزی همراه اول (۱۸ آبان ۱۴۰۵)، ویژه‌ی دانشجویان دانشکده‌ی مهندسی برق دانشگاه شهید بهشتی.

این نسخه **بدون سرور و بدون هزینه** اجرا می‌شود:

```
 دانشجو / برگزارکننده
        │  (مرورگر)
        ▼
 GitHub Pages ──────────►  Google Apps Script  ──────────►  Google Sheet
 (صفحه‌ها: docs/)          (پشتیبان: Code.gs)              (پایگاه‌داده)
  فقط ظاهر سایت             قوانین ثبت‌نام، ورود،           ثبت‌نام‌ها، تنظیمات،
                           قفل ظرفیت ۴۰ نفر               کاربران، گزارش
```

- **GitHub Pages** فقط فایل‌های ایستا نشان می‌دهد؛ برنامه‌ی سرور (Node) روی آن اجرا نمی‌شود. به همین دلیل منطق ثبت‌نام در **Google Apps Script** و داده‌ها در **Google Sheet** است.
- ظرفیت دقیقاً همان‌قدر که در تنظیمات گذاشته‌اید (پیش‌فرض ۴۰) پر می‌شود و با ثبت‌نامِ نفر آخر، ثبت‌نام **همان لحظه بسته می‌شود**. درخواست‌های همزمان با قفل (`LockService`) پشت‌سرهم پردازش می‌شوند، پس نفر ۴۱ هرگز تأیید نمی‌شود.
- پنل برگزارکنندگان فقط با نام‌کاربری و رمز باز می‌شود. صفحه‌ی پنل عمومی است (مثل هر سایت دیگر) اما **هیچ داده‌ای** بدون ورود از سرور خارج نمی‌شود.

## نصب، قدم‌به‌قدم (حدود ۲۰ دقیقه)

### ۱) ساختن Google Sheet
۱. به [sheets.google.com](https://sheets.google.com) بروید و یک Sheet **خالی** بسازید؛ اسمش را مثلاً «ثبت‌نام اردو همراه اول» بگذارید.
۲. نگران برگه‌ها نباشید؛ در مرحله‌ی بعد خودکار ساخته می‌شوند.

> از یک حساب Gmail شخصی (یا حسابی که دسترسی «Anyone» برایش مسدود نیست) استفاده کنید. بعضی حساب‌های دانشگاهی/سازمانی اجازه‌ی انتشار وب‌اپ برای همه را نمی‌دهند.

### ۲) گذاشتن کد پشتیبان (Apps Script)
۱. در همان Sheet: منوی **افزونه‌ها (Extensions) ← Apps Script**.
۲. فایل `Code.gs` را باز کنید، همه‌ی محتوایش را پاک کنید و محتوای فایل **`apps-script/Code.gs`** این مخزن را کامل جایگزین کنید. ذخیره کنید (Ctrl+S).
۳. بالای صفحه، از لیست توابع **`setup`** را انتخاب و **Run** را بزنید.
۴. Google اجازه می‌خواهد: **Review permissions ← حساب خودتان ← Advanced ← Go to … (unsafe) ← Allow**.
   (هشدار «تأییدنشده» طبیعی است؛ چون اسکریپت را خودتان نوشته‌اید/گذاشته‌اید و فقط به همین Sheet دسترسی می‌گیرد.)
۵. پایین صفحه **Execution log** را ببینید. رمز موقت مدیر آن‌جا نوشته می‌شود:
   ```
   نام‌کاربری: admin
   رمز عبور:  xxxxxxxxxxxx
   ```
   **همین حالا یادداشتش کنید**؛ دوباره نشان داده نمی‌شود (اگر گم شد، تابع `resetAdminPassword` را اجرا کنید).
۶. برگردید به Sheet؛ حالا برگه‌های «تنظیمات»، «ثبت‌نام‌ها»، «کاربران» و … ساخته شده‌اند.
۷. (اختیاری) تابع **`selfCheck`** را اجرا کنید؛ باید پیام «اتصال سالم است» بیاید.

### ۳) انتشار به‌عنوان وب‌اپ
۱. در Apps Script: **Deploy ← New deployment**؛ نوع (چرخ‌دنده) را **Web app** بگذارید.
۲. **Execute as: Me** و **Who has access: Anyone** (باید همین‌طور باشد، وگرنه دانشجوها به صفحه‌ی ورود Google می‌خورند).
۳. **Deploy** را بزنید و نشانی **Web app URL** را کپی کنید؛ به `/exec` ختم می‌شود.
۴. آزمایش: همان نشانی را با `?p=status` ته آن در مرورگر باز کنید. باید یک JSON ببینید که با `{"ok":true` شروع می‌شود.

### ۴) وصل کردن سایت به پشتیبان
فایل **`docs/js/config.js`** را باز کنید و نشانی را بگذارید:

```js
apiUrl: 'https://script.google.com/macros/s/AKfycb.../exec',
```

بقیه‌ی گزینه‌ها پیش‌فرض مناسبی دارند. (لوگوی همراه اول: فایلش را در `docs/assets/` بگذارید و نامش را جلوی `mciLogo` بنویسید، مثلاً `'assets/mci-logo.svg'`.)

### ۵) گذاشتن روی GitHub
۱. در GitHub یک مخزن **Public** بسازید (GitHub Pages رایگان فقط برای مخزن عمومی است). چیز محرمانه‌ای در مخزن نیست.
۲. همه‌ی فایل‌های این پوشه را آپلود کنید (Add file ← Upload files؛ یا با `git push`).
۳. **Settings ← Pages**: Source = *Deploy from a branch*، Branch = `main`، پوشه = **`/docs`** ← Save.
۴. بعد از یکی دو دقیقه سایت این‌جاست:
   - صفحه‌ی ثبت‌نام: `https://USERNAME.github.io/REPO/`
   - پنل برگزارکنندگان: `https://USERNAME.github.io/REPO/admin/`

### ۶) اولین ورود و تنظیم
۱. به `/admin/` بروید، با `admin` و رمز موقت وارد شوید. بلافاصله رمز تازه می‌خواهد.
۲. از بخش **تنظیمات**: زمان دقیق شروع، (در صورت نیاز) زمان پایان، ظرفیت، هزینه‌ی اردو، شماره‌کارت، محل و ساعت حرکت و راه‌های ارتباطی را بنویسید.
۳. از بخش **کاربران پنل** برای همکاران ستاد حساب «همکار» بسازید (آن‌ها کد ملی و اطلاعات مالی را نمی‌بینند، فقط حضور و پرداخت را ثبت می‌کنند).
۴. **فهرست دانشجویان دانشکده**: شماره‌های دانشجویی را در تنظیمات بچسبانید و گزینه‌ی «فقط دانشجویانِ فهرست زیر بتوانند ثبت‌نام کنند» را روشن کنید (پیشنهاد جدی؛ پایین‌تر توضیح داده‌ام).

## پیش از روز ثبت‌نام (چک‌لیست)

- [ ] یک **تمرین کامل** بکنید: زمان شروع را چند دقیقه بعد بگذارید، با چند گوشی ثبت‌نام کنید، ظرفیت را موقتاً ۳ بگذارید و ببینید نفر چهارم «ظرفیت تکمیل شد» می‌گیرد.
- [ ] بعد از تمرین، در **تنظیمات ← پاک‌سازی ثبت‌نام‌ها** داده‌ی آزمایشی را پاک کنید (رمز و عبارت تأیید می‌خواهد) و ظرفیت را به ۴۰ برگردانید.
- [ ] زمان شروع و ظرفیت را دوباره بررسی کنید. زمان شروع به وقت تهران است و با ساعت **سرور** سنجیده می‌شود، نه ساعت گوشی دانشجو.
- [ ] فهرست دانشجویان و شماره‌کارت را بررسی کنید.
- [ ] از لینک `…/exec?p=status` مطمئن شوید JSON برمی‌گرداند.
- [ ] Sheet را فقط با برگزارکنندگان لازم به اشتراک بگذارید (داخلش کد ملی و موبایل است).
- [ ] رمز مدیر را جای امن یادداشت کنید.

## نکته‌های مهم و محدودیت‌ها (صادقانه)

**۱. سرعت و ازدحام.** Apps Script ارزان و ساده است ولی سریع‌ترین گزینه نیست: هر درخواست معمولاً یک تا دو ثانیه طول می‌کشد و حدود ۳۰ اجرای همزمان بیشتر ندارد. برای ۴۰ صندلی و چند صد داوطلب کافی است، اما در لحظه‌ی شروع بعضی درخواست‌ها شلوغ می‌شوند. سایت این‌ها را خودکار جبران می‌کند: دکمه با ساعت سرور فعال می‌شود، درخواست‌های ناموفق چند بار با همان شناسه‌ی یکتا دوباره فرستاده می‌شوند (ثبت‌نام دوبل نمی‌شود)، و بعد از پر شدن ظرفیت، درخواست‌ها بدون خواندن Sheet رد می‌شوند. این بخش با شبیه‌ساز آزموده شده، اما **روی سرور واقعی Google نه**؛ حتماً تمرین بالا را با چند نفر واقعی انجام دهید.

**۲. فهرست دانشجویان را روشن کنید.** Apps Script نشانی IP کاربر را نمی‌دهد؛ پس محدودیت بر اساس IP ممکن نیست. تنها محافظ جدی در برابر ثبت‌نام افراد غیرمجاز یا ربات، فهرست شماره‌های دانشجویی دانشکده است. بدون آن، هر کسی با اطلاعات معتبر ظاهری می‌تواند ثبت‌نام کند. همچنین سایت یک تله‌ی ساده‌ی ربات و محدودیت تعداد تلاش برای پیگیری و ورود دارد.

**۳. حریم خصوصی.** Sheet شامل کد ملی و موبایل است. آن را فقط با افراد لازم به اشتراک بگذارید. خروجی «لیست حراست» را فقط برای همان کار بگیرید. مخزن GitHub هیچ داده‌ی شخصی ندارد.

**۴. در Sheet دستی ویرایش نکنید.** مرتب‌کردن (Sort) و فیلتر بی‌خطر است؛ ولی ویرایش سلول‌های برگه‌های «تنظیمات» و «کاربران»، حذف ردیف‌ها یا ستون‌های مخفی (Q تا S در «ثبت‌نام‌ها») می‌تواند داده را خراب کند. همه‌ی کارها را از پنل انجام دهید. رمزها در Sheet فقط به‌صورت درهم‌شده‌ی نمکی ذخیره می‌شوند و کلید مکمل آن (PEPPER) در Script Properties است، نه در Sheet.

**۵. قفل ورود.** پس از ۵ رمز اشتباه، آن نام‌کاربری ۱۵ دقیقه قفل می‌شود. این یعنی کسی که نام‌کاربری را بداند می‌تواند ورود را موقتاً ببندد؛ به‌خاطر نبود IP راه بهتری نیست. اگر رمز را فراموش کردید: `resetAdminPassword` را از ویرایشگر اجرا کنید.

**۶. ظاهر پنل عمومی است.** هر کسی می‌تواند فایل‌های پنل (HTML/JS) را ببیند؛ ولی بدون توکن ورود، سرور هیچ داده‌ای نمی‌دهد. توکن فقط در sessionStorage همان تب می‌ماند و با بستن تب پاک می‌شود. اعتبار هر نشست ۶ ساعت از آخرین فعالیت است.

## به‌روزرسانی کد

اگر `docs/js/shared.js`، `src/engine.js` یا `src/backend.js` را عوض کردید:

```bash
node tools/build.js      # فایل apps-script/Code.gs را از نو می‌سازد
npm test                 # ۵۵ آزمون (منطق، پشتیبان روی شبیه‌ساز Google)
```

سپس محتوای `Code.gs` را در Apps Script جایگزین کنید و **Deploy ← Manage deployments ← ✏️ ← Version: New version ← Deploy**. (نشانی `/exec` همان می‌ماند. فقط «Save» کافی نیست؛ بدون نسخه‌ی جدید، وب‌اپ کد قدیمی را اجرا می‌کند.)

## ساختار پوشه‌ها

| مسیر | کار |
|---|---|
| `docs/` | سایت ایستا (صفحه‌ی ثبت‌نام، پنل `admin/`، فونت، لوگو) که GitHub Pages نشان می‌دهد |
| `docs/js/config.js` | **تنها فایلی که باید ویرایش کنید**: نشانی وب‌اپ |
| `docs/js/gas-adapter.js` | واسطه‌ی ارتباط صفحه‌ها با Apps Script (تلاش مجدد امن، توکن ورود) |
| `src/engine.js` | همه‌ی قوانین ثبت‌نام: زمان، ظرفیت، قفل نفر آخر، لیست انتظار، آمار |
| `src/backend.js` | ذخیره در Sheet، قفل، ورود و نقش‌ها، مسیرها |
| `apps-script/Code.gs` | فایل آماده‌ی چسباندن در Apps Script (خروجی `tools/build.js`) |
| `test/` | آزمون‌های خودکار و شبیه‌ساز Apps Script |

## عیب‌یابی

| نشانه | علت و راه‌حل |
|---|---|
| نوار قرمز «اتصال به Google Sheet تنظیم نشده» | `apiUrl` در `docs/js/config.js` خالی یا اشتباه است |
| «اتصال برقرار نشد» / خطای `Failed to fetch` | Deploy با دسترسی **Anyone** نشده، یا نشانی `/exec` نیست؛ دوباره Deploy کنید |
| تغییر کد اثر نکرد | نسخه‌ی جدید Deploy نکرده‌اید (بخش به‌روزرسانی) |
| «سامانه شلوغ است» | قفل چند ثانیه مشغول بوده؛ سایت خودکار دوباره می‌فرستد |
| در Sheet نوشته‌ها خالی است | `setup` اجرا نشده یا Apps Script از داخل همین Sheet ساخته نشده است |
| «Service invoked too many times» | سقف سهمیه‌ی روزانه‌ی Google؛ چند ساعت بعد دوباره امتحان کنید یا ازدحام را کم کنید |
